Execution plan for the AI agent

Phase B (core pipeline) must land before Phase D/E (transports), because both transports call into BridgeService.submit. Phase C (GitHub adapter) can run in parallel with Phase D/E once Phase A+B land.

Path caveat: I have the class names and module names from the repository, but not the exact src/main/kotlin/... package paths. Phase B — Core pipeline (bridge/core)

6. Implement the request pipeline

· File: BridgeService.kt (replace the TODO("implement the spec 6.2 pipeline") in submit).
· Deliverable: RECEIVED → AUTHORIZED → (AWAITING_APPROVAL) → EXECUTING → SUCCEEDED | FAILED, plus OUTCOME_UNKNOWN on lost acknowledgement after the GitHub call.
· Acceptance: transition edges exactly match RequestState.kt and lifecycle.v1.json; no edge involving MANUAL_REVIEW or CANCELLED is used (those are still proposals).
· Tag: [Scaffold or stub].

7. Implement the policy engine

· File: PathNormalizer.kt.

· Tag: [Scaffold or stub], depends on Task 1.

9. Implement protected-path matching

· File: ProtectedPaths.kt (currently returns true for everything).

10. Implement branch write rules

11. Implement allow-list canonicalization

12. Implement approval gating

13. Implement write serialization

· File: WriteCoordinator.kt (serialize is TODO).
· Deliverable: per-repo (or per-repo-branch) mutex so concurrent write_file / create_branch don't race.

14. Implement duplicate detection

· File: DuplicateDetector.kt (fingerprint is TODO).
· Deliverable: fingerprint = request_id + operation + normalized arguments; suppress replay of the same fingerprint within the delivery window from Task 3.
· Acceptance: replaying the same request_id after SUCCEEDED returns the cached result without a second GitHub call.
· Tag: [Scaffold or stub], depends on Task 3.

15. Implement outcome reconciliation

· File: OutcomeReconciler.kt (reconcile is TODO("read-back reconciliation")).
· Deliverable: for write_file, read the target branch/file (or the PR) and compare against the intended commit/content hash without storing content in the audit record; map result to SUCCEEDED, FAILED, or MANUAL_REVIEW.
· Acceptance: simulated lost ack on write_file reconciles to SUCCEEDED when the commit is present and FAILED when absent; no blind replay (RTB-43, RTB-44).
· Tag: [Scaffold or stub], depends on Tasks 3 and 16.

Phase C — GitHub adapter (bridge/github)

16. Implement the GitHub REST client

· File: GitHubAdapter.kt (currently throws NOT_IMPLEMENTED).
· Deliverable: four operations — GET /repos/{o}/{r}/contents/{path} (read_file), POST /repos/{o}/{r}/git/refs after resolving base commit (create_branch), contents write after resolving existing file SHA (write_file), POST /repos/{o}/{r}/pulls (create_pull_request). The phone resolves file SHA and base commit SHA itself; the agent never supplies them (RTB-15).
· Acceptance: contract tests against mocked REST responses for success, conflict, and 429; GitHubAdapter never logs request/response bodies or the PAT.
· Tag: [Scaffold or stub], depends on Task 5 for the PR shape.

17. Implement rate-limit and upstream error mapping

· Files: RateLimitHandler.kt and UpstreamErrorMapper.kt (both scaffold-only).
· Deliverable: map 403/429 with rate-limit headers to a typed retryable error with backoff bounded per the decision in Task 3; map 409/422 to conflict; map everything unmapped to a non-retryable upstream error.
· Acceptance: 429 with Retry-After produces the documented backoff; conflict on write_file returns the typed conflict error and does not auto-retry.
· Tag: [Scaffold or stub] + [Open decision] on the backoff bounds.

Phase D — Local transport (bridge/local, bridge/app)

· Tag: [Scaffold or stub], depends on Task 2.

19. Implement local authentication

· File: LocalAuthPlugin.kt.

· Tag: [Scaffold or stub].

· Deliverable: POST /api/v1/tools/{operation} matching the OpenAPI contract; the path operation must equal the envelope’s operation; only the six canonical operations are routable.
· Acceptance: unknown operation → 404; path/envelope mismatch → 400; all six routes dispatch to BridgeService.
· Tag: [Scaffold or stub].

21. Implement the local envelope mapper

· File: LocalEnvelopeMapper.kt.
· Deliverable: HTTP + JSON → canonical RequestEnvelope (RFC 3339 → epoch millis) and ResponseEnvelope → HTTP; reject unknown fields; enforce the 2097152-byte request cap before JSON parsing.
· Acceptance: oversize body → typed error before parse; SUCCEEDED with error present → rejected by the response serializer.
· Tag: [Scaffold or stub].
