## 1. Local Transport Response Model (A2 + A3)

**Question:** For each of the six operations, should the local HTTP endpoint return a synchronous `200` with the final result, or a `202 Accepted` + poll via the status endpoint?

**Default recommendation:**
- `read_file` / `list_branches` → synchronous `200`
- `create_branch` / `write_file` / `delete_file` / `create_pull_request` → `202` + poll

## 2. Lifecycle Edges & Cancel Route (A3)

**Question:**  
a) Should `MANUAL_REVIEW` and `CANCELLED` be first-class states in the lifecycle?  
b) Should a cancel route exist on the local transport?

**Default recommendation:**  
- Yes to both.  
- Transitions:  
  - Any non-terminal state → `CANCELLED` (via cancel route or expiry)  
  - `OUTCOME_UNKNOWN` → `MANUAL_REVIEW` when reconciliation cannot decide  
- Cancel route: `POST /v1/requests/{id}/cancel` (idempotent)

**Your answer:**  
accept default

## 3. `create_pull_request` Head Syntax & Existing-PR Behaviour (A5)

**Question:**  
a) Accepted `head` values? (`branch` only, or also `owner:branch`?)  
b) When an equivalent open PR already exists, should the operation return an error or the existing PR (idempotent)?

**Default recommendation:**  
- Accept both `branch` and `owner:branch`  
- Idempotent: return the existing PR with status `SUCCEEDED` and a note that it already existed

## 4. Repository Name Canonicalisation (A6)

**Question:** How should repository names be handled (case, renames)?

**Default recommendation:**  
- Normalise to lowercase  
- Accept the current canonical name only (do **not** automatically follow renames)  
- Reject any other form with a typed error

**Your answer:**  
accept default

## 5. Default Protected Lists (A6)

**Question:** Confirm or adjust the default protected branches and paths.

**Default recommendation:**  
- Protected branches: `main`, `master`  
- Protected paths: `.github/workflows/**` and any path containing policy/config files (unless explicitly enabled)  
- Everything else is writable subject to the allow-list and confirmation rules

**Your answer:**  
accept default

## 7. Error Catalog & Retry Bounds (A4)

**Question:** Confirm backoff bounds and that `OUTCOME_UNKNOWN` remains non-retryable.

**Default recommendation:**  
- Backoff: initial 1 s, max 60 s, exponential with jitter (from `DV-RTB-BACKOFF`)  
- `OUTCOME_UNKNOWN` → `retryable: false`  
- All other codes follow the mapping already partially present in `error.v1.json`

**Your answer:**  
accept default
